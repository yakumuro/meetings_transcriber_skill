# Транскрибация встреч

Запрос пользователя: $ARGUMENTS

Используй скрипты и шаблоны из папки этого навыка. Не вписывай абсолютные пути конкретного компьютера в этот файл. Определи корень пакета по расположению навыка и выполняй команды из этого корня. Все пути заключай в кавычки.

## Обязательная проверка перед любым ответом

При **любой активации этого навыка** сначала проверь наличие `config.json`, ещё до классификации запроса и до ответа пользователю. Это относится к Start, запуску транскрибации, вопросам «Че там с транскрибами?», проверке статуса, списку записей и поиску по встречам.

Если `config.json` отсутствует, **всегда немедленно запускай полный сценарий Первый Start**. Не выводи вместо установки отчёт о пустой очереди, пустом `recordings/` или пустом `outputs/`. Ответ «транскрибов нет, добавьте запись» без запуска установки запрещён.

До завершения установки:

- не выполняй `list` или `status` и не проверяй записи;
- не используй отсутствие файла, записей или готовых результатов как причину отмены настройки;
- не останавливайся после `detect` или рекомендаций — предложи выбор модели и выполни `setup`;
- не ограничивайся инструкцией пользователю — сам продолжи установку;
- сохрани исходный запрос и после успешного `doctor` вернись к нему.

Только после создания конфигурации и успешной установки можно проверять записи, очередь, результаты или архив. Если записей затем нет, сначала сообщи, что настройка завершена, и уже затем попроси добавить запись.

## Выбор сценария

- `Start`, `Transcribation Start`, `Transcription Start` или просьба настроить навык — выполни **Настройку**.
- Просьба транскрибировать аудио или видео — выполни **Транскрибацию**.
- Просьба проверить ход транскрибации — после обязательной проверки конфигурации выполни `scripts/meetings.py status`.
- Явная просьба найти прошлые обсуждения или решения — после обязательной проверки конфигурации выполни **Поиск по архиву**.
- Не читай архив встреч при запросах, которые его не касаются.

Выбери доступный запускатель Python 3: `python3`, `python` или `py -3` в Windows. В примерах используется `python3`; при необходимости замени только запускатель, сохранив аргументы.

## Правило интерактивных вопросов

Если IDE или агент предоставляет инструмент структурированных вопросов и вариантов ответа, используй его при настройке. Это относится к совместимым интерфейсам Cursor, Kimi Code, Claude Code, Codex и других агентов. Наличие возможности определяй по фактически доступным инструментам, а не только по названию продукта.

Если такого инструмента нет, задай вопрос в чате с нумерованными вариантами. Принимай как номер варианта, так и ответ в свободной форме. Отсутствие интерактивного интерфейса не должно блокировать настройку.

## Настройка

### Первый Start

1. Выполни:

   ```bash
   python3 scripts/meetings.py detect
   ```

2. Покажи обнаруженные ОС, архитектуру, число потоков CPU, RAM, GPU и VRAM, если они известны, рекомендуемый backend и наличие FFmpeg. Явно отметь неопределённость диагностики.
3. Предложи модели из `model_recommendation.options`. Отметь рекомендованный вариант, но разреши выбрать любую модель из списка. Используй интерактивный интерфейс хоста, а при его отсутствии — нумерованный список.
4. Значения по умолчанию: backend `auto`, язык распознавания `auto`, язык саммари `ru`, VAD включён. Для `tiny`, `base` и `small` в Windows/Linux режим auto намеренно использует компактный CPU-пакет и не скачивает CUDA. Сообщи это пользователю при выборе такой модели. Для явного GPU-ускорения пользователь должен отдельно выбрать CUDA/Vulkan. Перед установкой системных пакетов или использованием прав администратора запроси согласие.
5. Спроси, какие артефакты создавать после транскрибации. `transcript.md` обязателен и не предлагается как отключаемая опция. Отдельно спроси о `summary.md` (по умолчанию да) и `email.md` (по умолчанию нет). Если интерфейс поддерживает множественный выбор, предложи пункты «Саммари» и «Email-протокол»; иначе задай два вопроса «да/нет» или дай нумерованные варианты. Сообщи, что email.md — короткий текст письма для копирования, а не автоматическая отправка.
6. После выбора пользователя выполни:

   ```bash
   python3 scripts/meetings.py setup --model "<выбранная-модель>" --backend auto --summary --no-email
   ```

   Замени флаги артефактов на фактический выбор: `--summary` или `--no-summary`, `--email` или `--no-email`. Если хост поддерживает фоновые задачи, используй их для длительного скачивания или сборки. Не меняй самовольно выбранную модель, явно выбранный backend или артефакты. Если в режиме auto возвращены `warnings` и выполнен fallback на CPU, обязательно покажи их пользователю.
7. Выполни:

   ```bash
   python3 scripts/meetings.py doctor
   ```

   `doctor` должен успешно выполнить реальную тестовую транскрибацию. Не считай установку успешной только по наличию файлов.
8. Покажи выбранные модель, backend и артефакты, путь к `config.json` и краткую инструкцию: поместить записи в `recordings/`, попросить транскрибировать последнюю встречу и задать вопрос по прошлым встречам. Если настройка была запущена из запроса на транскрибацию, вернись к исходной записи.

### Повторный Start

1. Прочитай активную конфигурацию через `scripts/meetings.py config`.
2. Выполни `scripts/meetings.py doctor --quick`.
3. Покажи текущие модель, backend и настройки `artifacts`. Предложи продолжить, сменить модель, backend, артефакты или повторить диагностику. Не переустанавливай компоненты автоматически.
4. Для изменения конфигурации задай вопрос по правилу интерактивных вопросов и повтори `setup` с выбранными параметрами, включая флаги `--summary/--no-summary` и `--email/--no-email`.

## Транскрибация

1. Всегда проверь наличие `config.json` до проверки записей, статуса задания и любых попыток транскрибации.
2. Если конфигурации нет, сообщи: «Транскрибация пока не настроена. Давайте настроим её сейчас: определим оборудование и выберем модель». Немедленно выполни **Первый Start**, даже если `recordings/` пуст или пользователь не указал файл. Запрещено прекращать работу из-за отсутствия записей, ограничиваться `detect` или просить пользователя вручную запустить установку. Сохрани исходный запрос и выбранный файл, если он был указан.
3. После успешных `setup` и полного `doctor` автоматически вернись к исходному запросу без повторной просьбы пользователя. Если файл был указан, продолжи его обработку. Если файл не был указан, только теперь проверь записи; при их отсутствии сообщи, что установка завершена, и попроси добавить запись.
4. Если `config.json` уже существует, выполни `scripts/meetings.py doctor --quick`. При успешной проверке переходи к следующему шагу. При ошибке сообщи, что настройка не завершена или требует восстановления, покажи причину и выполни сценарий **Повторный Start**; не запускай транскрибацию с неисправной конфигурацией.
5. Проверь `scripts/meetings.py status`. Если задание выполняется, не запускай второе и не останавливай текущее.
6. Найди записи через `scripts/meetings.py list --days 1`. Если записей нет, попробуй `--days 7`, затем `--all`.
7. Выбирай файлы только из результатов скрипта. Точное имя, путь, ID или уникальный фрагмент от пользователя можно обработать напрямую. Для запроса «последняя» выбери `latest_recording` и сообщи, какой файл взят. При неоднозначности верни нумерованный список кандидатов.
8. Если `already_transcribed` равно true, не обрабатывай запись повторно без явного решения пользователя. Скрипты не разрешают перезапись.
9. Запусти встроенный фоновый режим:

   ```bash
   python3 scripts/meetings.py transcribe "<относительный_путь_или_имя>" --background
   ```

10. Убедись, что получено `started: true`, затем наблюдай через механизм фоновых задач хоста. Не опрашивай статус слишком часто. При ошибке запуска прочитай логи, указанные в JSON.
11. После завершения проверь `status` и полностью прочитай полученный `transcript.md`. Не создавай дополнительные артефакты по неполному или неуспешному транскрипту.
12. Прочитай `artifacts` из `config.json`: transcript обязателен, summary и email создаются только при включённых настройках. Для старой конфигурации без блока artifacts используй summary=true и email=false.
13. Если `artifacts.summary` равно true, создай `summary.md` в той же папке по шаблону `templates/summary.md`. Используй язык `transcription.summary_language`. Опирайся только на факты транскрипта; не выдумывай решения, ответственных и сроки.
   - Располагай темы по смыслу и хронологии.
   - Явные договорённости кратко укажи в отдельном разделе.
   - Если следующих шагов нет, напиши «Следующие шаги не зафиксированы» вместо пустой таблицы.
   - Не создавай раздел дополнительных пунктов без содержимого.
   - Если настройка выключена, не создавай summary.md.
14. Если `artifacts.email` равно true, создай `email.md` по `templates/email.md`. Это короткий протокол для копирования в почтовый клиент, а не отправка письма. Используй язык `transcription.summary_language`, только факты транскрипта и/или созданного саммари, без Markdown-заголовков и полного пересказа. Удали пустые разделы. Если настройка выключена, не создавай email.md.
15. После завершения всех выбранных артефактов добавь встречу в `outputs/REGISTRY.md`:

   ```bash
   python3 scripts/meetings.py registry add \
     --folder "<папка_результата>" \
     --date "<ГГГГ-ММ-ДД>" \
     --topics "<3–6 коротких тем>" \
     --decisions "<1–2 кратких решения>"
   ```

   Используй дату записи из метаданных и факты транскрипта. Реестр обновляется также при выключенных summary и email. Команда проверяет transcript, запрещает дубликаты и добавляет новую запись в начало таблицы.
16. Проверь обязательные `transcript.md` и `metadata.json`, только включённые `summary.md`/`email.md` и строку реестра. Верни папку результата и точные пути к созданным файлам. При ошибке сообщи состояние задания, логи и созданные частичные файлы; не выдавай частичный результат за успешный.

## Поиск по архиву

Этот сценарий работает только на чтение.

1. Прочитай `outputs/REGISTRY.md` или используй `scripts/meetings.py registry search "<запрос>"` для буквальной фильтрации кандидатов.
2. Выбирай кандидатов по дате, папке, темам и решениям. Не открывай все встречи подряд.
3. Для релевантных встреч читай только `summary.md`. Не используй `email.md` при поиске.
4. Открывай `transcript.md`, если саммари отсутствует или его недостаточно, нужна точная формулировка либо проверка спорной детали.
5. Отвечай только по прочитанным фактам. Для каждого существенного вывода указывай дату и папку встречи.
6. Если совпадений нет, прямо скажи об этом. Отсутствие записи в реестре не доказывает, что тема никогда не обсуждалась.
7. При поиске не изменяй `REGISTRY.md`, `summary.md`, `email.md`, `metadata.json` и `transcript.md`.

## Безопасность и конфиденциальность

- Не удаляй исходные записи.
- Не перезаписывай готовые результаты и не останавливай активную транскрибацию вручную.
- Не добавляй в Git модели, runtime-файлы, логи, локальную конфигурацию, записи и результаты; правила уже заданы в `.gitignore`.
- Распознавание Whisper выполняется локально. Саммари и email-протокол создаёт выбранный агент или модель, поэтому текст может обрабатываться по правилам соответствующего провайдера. Не утверждай, что весь процесс агента полностью офлайн.
